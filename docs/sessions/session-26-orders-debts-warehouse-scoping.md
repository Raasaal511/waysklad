## Что сделано

1. **№22 — `POST /api/orders` возвращал `number: null`.** `SqlAlchemyOrderRepository.add()`
   присваивал `order.id`, но не прокидывал обратно сгенерированный `order.number`.
   Теперь номер сразу в ответе создания.
2. **№9 — `GET /api/inventory/documents/{id}`.** Точечный запрос документа склада
   вместо `listDocuments()` + фильтрации на клиенте. Доступ для warehouse-scoped
   сотрудников проверяется по складу документа (для перемещения — по любому из двух).
3. **№7 (частично) — сверка баланса на дату.** `GET /api/debts/client/{id}` и
   `/supplier/{id}` принимают `?on=YYYY-MM-DD` — снимок баланса и погашений на
   произвольную дату в прошлом. Полноценная «сверка одной кнопкой» (акт/документ)
   по-прежнему не реализована — физический формат так и не определён.
4. **№5 (частично) — warehouse-скоуп для заказов/долгов.** `Debt` получил
   обязательное поле `warehouse_id` (миграция с backfill: долг из продажи/приёмки
   берёт склад документа-источника, ручной долг — первый склад тенанта). Заказы и
   долги (списки и одиночные) теперь фильтруются по складам сотрудника так же, как
   уже было у продаж/остатков/документов. `Client`/`Supplier` сами по себе всё ещё
   без warehouse_id — не полностью закрывает №5, только его часть про Order/Debt.

Заодно устранён N+1 в `SqlAlchemyOrderRepository` (единицы измерения товаров
батчатся один раз на список заказов) и вынесен повторяющийся код фильтрации
долгов по складу в `debts/router.py`.

**Breaking-изменение:** `POST /api/debts` и `POST /api/debts/suppliers` теперь
требуют `warehouse_id` в теле запроса. Отчёт для фронтенда —
`frontend/api_docs/orders_debts_warehouse_scoping.md`.
