## Audit — журнал действий

Реализован по образцу остальных модулей (domain → infrastructure → application → presentation),
чтобы не откладывать и не копить долг, как предлагалось.

- `domain/audit/entities.py` — `AuditEntry` + фабрика `AuditEntry.record(actor, action, entity_id, **details)`
- `domain/audit/repository.py` — `IAuditRepository` (add, list_recent)
- `infrastructure/db/mappers/audit.py` + `repositories/audit.py` — реализация, `uow.audit`
- Запись добавлена во ВСЕ мутирующие use case'ы (14 шт.): регистрация магазина, создание
  сотрудника, создание/изменение товара, все 4 складских документа, продажа, долг
  (выдача/погашение/рассрочка), заказ (создание/статус), клиент, поставщик.
  Запись — в той же транзакции, что и основная операция (одна строка перед `uow.commit()`).
- `GET /api/audit` — доступен только роли с правом `AUDIT_VIEW` (owner, analyst) через
  новый `require_permission(permission)` в `deps/auth.py`, применяется на уровне роутера
  (`APIRouter(dependencies=[...])`), не в каждом эндпоинте.

## conftest.py — общие фикстуры (устраняет дублирование между 4 файлами тестов)

Раньше `make_uow`/`client`/`_phone()`/`_register()` были продублированы в
test_repositories.py, test_use_cases.py, test_api.py. Вынесено в `tests/conftest.py`:

| Фикстура | Назначение |
|---|---|
| `random_phone` | фабрика уникальных телефонов |
| `db_session_factory` | чистая схема `waysklad_test` на тест; skip, если postgres недоступен |
| `make_uow` | фабрика `SqlAlchemyUnitOfWork(tenant_id)` поверх тестовой БД |
| `hasher` | `BcryptPasswordHasher()` |
| `create_shop` | tenant+owner напрямую через репозитории (для тестов репозиторного слоя) |
| `registered_shop` | tenant+owner через `RegisterShopUseCase` (для тестов use case/бизнес-правил) |
| `warehouse_id` | id склада, созданного при регистрации |
| `create_product` | товар напрямую через репозиторий (когда создание товара — не предмет теста) |
| `client` | httpx AsyncClient с подменённой БД (для API-тестов) |
| `owner_headers` | Authorization-заголовок владельца, зарегистрированного через HTTP |

Также убрал докстроки в начале test_repositories.py/test_use_cases.py (были добавлены
до того, как это правило появилось) — для единообразия с остальными файлами.

## Новые тесты (25 шт., итого 49)

- **repositories**: сохранение товара с синком вариантов (delete-orphan), сохранение долга
  (погашения дописываются, график заменяется целиком), сохранение заказа (save не трогает
  строки), поставщик, поиск клиента + сохранение лимита долга
- **use cases**: обновление товара (+ запрет для продавца), списание, перемещение между
  складами, инвентаризация с расхождением, лимит долга без продажи, несовпадение суммы
  графика рассрочки с остатком, кладовщик может приёмку/не может продажу, поставщик+клиент
- **api**: списание+инвентаризация через HTTP, полный жизненный цикл заказа (все статусы +
  запрет пропуска), 422 на невалидный пароль, 404 на несуществующий товар
- **permissions**: кладовщик не управляет долгами/заказами/клиентами, matrix-проверка
  «manager ⊇ seller ∪ storekeeper», параметризованный тест по всем 5 ролям
