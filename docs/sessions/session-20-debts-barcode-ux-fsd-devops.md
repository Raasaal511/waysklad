# Сессия 20 — Долги/штрихкоды доведены до конца, кастомные UI-компоненты, FSD, DevOps

**Этап плана:** 7 (долги), 6 (доработка штрихкодов), внеплановая инженерная сессия (UI-компоненты, структура фронтенда, Docker)

## Контекст
Продолжение сессии 19 (профиль/недостающие действия). Пользователь запросил
модуль долгов «Всё одним проходом», довёл до конца сканирование штрихкодов,

профессиональную сборку Docker без усложнения проекта, кастомные UI-компоненты

же объект используется больше 1 раза — сделать компонент»), и переразметку
фронтенда по FSD.

### Штрихкоды и сканирование (добор недели 6)
- Домен `Barcode` расширен с цифр-only (4–14) до `^[A-Z0-9\-]{4,32}$`
  (буквы/цифры/дефис, нормализация в uppercase) — по факту оказалось, что
  реальные штрихкоды производителей бывают буквенно-цифровыми (Code128/39), не
  только EAN/UPC. Миграция `c8a2d6e5f1b9` расширяет колонки `barcode` до
  `String(32)`.
- Явные проверки уникальности штрихкода в `CreateProductUseCase`/
  `UpdateProductUseCase` (по товару и по вариантам) + `IntegrityError` → 409
  как страховочный обработчик.
- Переход с нативного `BarcodeDetector` (не поддерживается в Safari/iOS) на
  `@zxing/library` — `BrowserMultiFormatReader`, поддержка QR добавлена
  заодно. Обнаруженный по ходу регресс размера бандла (335→788 КБ) устранён
  вынесением `BarcodeScanner` в отдельный `React.lazy`-чанк — главный бандл
  вернулся к 334 КБ, сканер грузится только при открытии (453 КБ/120 КБ gzip
  отдельно).
- Поддержка аппаратных USB/Bluetooth-сканеров через детекцию скорости
  ввода в глобальном `keydown` (интервал <60мс между символами — сканер, не
  человек за клавиатурой).
- Найден и исправлен баг: единица «шт» могла показывать дробное количество в
  корзине — `addToCart` не учитывал `isFractional` при отсечении по остатку
  (учитывал только `stepLineQuantity`).

### Кастомные UI-компоненты (вместо нативных элементов)
- `shared/ui/Button.tsx`, `IconButton.tsx` — варианты
  primary/secondary/danger/ink/accent-outline (Button),
  danger/muted/accent (IconButton). Все ~60 использований `<button>` по 13
  страницам и `BarcodeScanner` заменены.
- `shared/ui/Select.tsx` — полностью кастомный dropdown (не нативный
  `<select>`): триггер-кнопка + список через `createPortal`, клавиатурная
  навигация (стрелки/Enter/Esc), закрытие по клику вне. Все ~17 `<select>` по
  проекту заменены.
- `shared/ui/DateInput.tsx` — свой календарь-попап взамен `<input
  type="date">`, тот же ISO-строковый контракт value/onChange, что и нативный
  инпут (не потребовалось менять логику стейта на страницах). Все 6
  использований заменены.
- Часть замены (SalePage, самая большая и сложная страница — 1700+ строк)
  выполнена фоновыми агентами с точным маппингом правил (className
  `input-required` → проп `required`, enum-select → `Object.entries`, и т.д.),
  результат проверен вручную построчно на предмет случайных изменений
  поведения (CSS-специфичность bespoke-классов типа `.sale-history-row`).

### Frontend по Feature-Sliced Design
Выбран облегчённый вариант FSD (3 слоя вместо канонических 5) — по размеру
проекта (13 страниц, соло-разработчик) полный `app/pages/widgets/features/
entities/shared` создал бы много пустых прослоек ради единственной формы на
странице. Финальная структура:
- `entities/{product,debt,sale,counterparty,inventory,order,profile,auth,
  analytics}/api.ts` — вся API-логика по сущностям (бывший `src/api/*.ts`).
- `entities/debt/debtStatus.ts`, `entities/barcode/{BarcodeScanner,
  barcodeSupport}` — код, привязанный к конкретной сущности/фиче.
- `shared/api/client.ts`, `shared/lib/format.ts`, `shared/ui/*`.
- `pages/*` — страницы с формами внутри, без искусственного дробления на
  `features/` (не оправдано для форм, использующихся один раз на одной
  странице).
- `app/*` — routing/providers/layout, без изменений.
Старые `src/api/`, `src/lib/`, `src/components/` удалены полностью.

### DevOps — Docker
- `backend/Dockerfile`: `PYTHONDONTWRITEBYTECODE`/`PYTHONUNBUFFERED`/
  `PIP_NO_CACHE_DIR`, non-root пользователь (`uid 1000`), `HEALTHCHECK`.
- `frontend/Dockerfile` (prod): `HEALTHCHECK`.
- `frontend/nginx.conf`: gzip (был выключен по умолчанию в `nginx:alpine`),
  `Cache-Control: immutable` для хэшированных Vite-ассетов, и — обнаруженный
  проактивным тестированием, не запрошенный явно — фикс реальной уязвимости
  продакшена: nginx падал целиком (`nginx -t` → `host not found in upstream`)
  при недоступном на старте `backend`, что убивало отдачу даже статики при
  рестарте контейнера. Исправлено через ленивое DNS-разрешение Docker
  (`resolver 127.0.0.11` + `set $backend_upstream` + `proxy_pass
  $backend_upstream`).
- `docker-compose.prod.yml`: healthcheck для `db`, `depends_on: condition:
  service_healthy` вместо списковой формы для `backend`/`frontend`.
- По ходу пойман и исправлен второй баг: `HEALTHCHECK` с `localhost` вместо
  `127.0.0.1` падал с connection refused внутри контейнера
  (IPv4/IPv6-резолюция) — исправлено в обоих Dockerfile.
