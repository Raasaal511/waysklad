# Сессия 05 — Value object для телефона (phonenumbers)

**Дата:** 2026-08-04
**Этап плана:** укрепление identity/counterparties (недели 1–2) перед переходом к неделям 3–4

## Зачем
Телефон хранился как голая строка — один и тот же номер мог попасть в базу как
`+79280001122`, `89280001122` и `9280001122`, ломая уникальность `users.phone`, поиск
клиентов и будущие WhatsApp-ссылки. Обсудили — решили использовать `phonenumbers`
(Python-порт libphonenumber), а не самодельные регексы.

## Что сделано

- `domain/common/phone.py` — `Phone`, value object по образцу `Barcode`/`Money`:
  принимает национальный формат (`89280001122`, `9280001122`) и международный
  (`+79280001122`), приводит к единому E.164, регион по умолчанию `RU`. Невалидный
  ввод → `DomainError`.
- `User.phone: Phone` (было `str`), `Client.phone`/`Client.whatsapp: Phone | None`
  (было `str = ""`). `Supplier.contact` не тронут — это не всегда телефон (может быть
  email/telegram), форсировать тип не стали.
- Мапперы (`identity.py`, `counterparties.py`): `to_orm` — `str(phone)`, `to_entity` —
  `Phone(model.phone)` / `None` если пусто. В БД по-прежнему просто `String` — миграция
  не нужна.
- Use cases (`register_shop`, `login`, `create_employee`, `create_client`): строка из
  запроса оборачивается в `Phone(...)` в начале сценария — если формат некорректный,
  `DomainError` (400). В `login` невалидный формат превращается в `AccessDeniedError`
  («неверный телефон или пароль»), а не в 400 — чтобы не раскрывать, что телефон
  распознан, но не найден, вместо просто «некорректен» (тот же принцип единого
  сообщения, что уже был в login).
- Presentation: `UserResponse`/`ClientResponse` сериализуют `str(phone)` — формат
  ответа API не изменился (по-прежнему строка).
- requirements.txt: `phonenumbers>=8.13`.

## Тесты
- `tests/test_phone.py` (новый, 6 тестов) — нормализация трёх форматов к одному
  E.164, равенство `Phone` из разных форматов ввода, отказ на мусор и слишком
  короткий номер.
- `tests/conftest.py`: `random_phone` генерировал `uuid4().hex[:9]` — это могло
  включать буквы a-f и ломало номер; переделано на `random.choices("0123456789")`.
- Прямые конструкции `Client(phone="...")` в test_repositories.py обёрнуты в `Phone(...)`
  (аналогично тому, как `Barcode(...)` уже оборачивался).
- Итого тестов: 55 (было 49).
