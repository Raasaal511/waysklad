# Сессия 15 — Подключение Telegram и сверка MVP

**Дата:** 2026-08-05
**Этап плана:** недели 11-12 (README п. 8) — backend-часть

## Контекст
Недели 11-12 по README — демо-аккаунты, лендинг, видео-инструкции, пилот
(внедрение в 5–10 реальных магазинах). Это почти целиком не-код работа
(контент, обучение, продажи) или фронтенд (лендинг). Единственная реальная
backend-задача из этого диапазона — закрыть TECH_DEBT #1 (заведён в сессии 14):
не было use case «подключить Telegram», из-за чего уже готовый бот (сессия 13)
не мог технически дойти ни до одного реального магазина — `Tenant.owner_
telegram_chat_id` выставлялся только напрямую в БД. Это нужно было закрыть до
пилота — сделано в этой сессии, а не отложено дальше.

## Что сделано
- **`Permission.SETTINGS_MANAGE`** (новое право) — только у `Role.OWNER`
  (входит в `frozenset(Permission)`, не добавлено ни в один из
  `_SELLER`/`_STOREKEEPER`/`_ANALYST`/`_MANAGER` наборов — управляющий
  настройки магазина не трогает, аналогично тому, как он не видит
  `ANALYTICS_VIEW`).
- **`application/auth/connect_telegram.py`**: `ConnectTelegramUseCase` —
  сохраняет `chat_id` в `Tenant.owner_telegram_chat_id` через новый
  `ITenantRepository.save()` (раньше был только `add`), пишет audit-запись
  `shop.connect_telegram`.
- **`POST /api/auth/telegram`** — принимает `chat_id`, возвращает
  `TenantResponse`. Отдельного эндпоинта «получить настройки магазина» не
  делал — не запрашивалось чек-листом, YAGNI.

## Проверено
98 тестов (было 96): `ConnectTelegramUseCase` сохраняет chat_id и отклоняет
не-владельца (`AccessDeniedError` для управляющего); API-тест на весь цикл,
включая 403 для продавца. Живой `uvicorn` + `waysklad_dev`: подключение
Telegram-чата через реальный HTTP-запрос отработало корректно. `compileall`
— чисто.

до отдельной команды перейти к фронту.

## TECH_DEBT — статус реестра
Пункт #1 (Telegram-подключение) закрыт этой сессией. Остаются открытыми:
#2 (sync принимает только продажи, не возвраты/приёмки/списания) и #3
(типизация ошибок в offline-пачке) — оба некритичны для MVP-пилота, где
основной офлайн-сценарий — розничная продажа.

## Дальше
Backend-часть MVP (README §5.1) полностью закрыта и протестирована (98
тестов). Дальнейшая работа по плану — либо фронтенд (PWA, экраны, офлайн-
