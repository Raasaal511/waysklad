# Язык анимаций (motion language)

Зафиксировано перед массовым применением по проекту, по запросу пользователя:
рабочий инструмент для кассиров/кладовщиков, которые в нём весь день — фидбэк
должен быть, чтобы интерфейс не ощущался мёртвым, но без резких/дёрганых
эффектов и без утомляющей суеты на каждый клик. Итог трёх раундов правок на
`WarehouseDetailPage`/`StockPage`/`SalePage` в этой сессии: 3D-подъём
(`scale`+тень одновременно) был отвергнут как «дешёвая имитация» — решили
оставить только смену фона на акцентный + при необходимости тонкую тень без
сдвига геометрии. Это и есть базовое правило ниже.

## Правило 1 — идентичное поведение входа и выхода

Один и тот же `transition` должен работать в обе стороны (наведение/уход,
открытие/закрытие). Никогда не задавать анимацию только на `:hover`, оставляя
возврат мгновенным — именно это вызвало жалобу «дёргается».

```css
.el {
  transition: background-color 0.15s ease;
}
.el:hover {
  background: var(--accent-soft);
}
```

## Правило 2 — фидбэк без смещения геометрии

Наведение на кликабельный элемент в списке/таблице — только смена фона
(`var(--accent-soft)` или `var(--accent-soft-weak)`), без `transform: scale()`
и без `box-shadow`, если элемент часть плотного списка (нарушает соседние
строки визуально, читается как «баг», не «отклик»). Тень + лёгкий подъём
(`translateY(-2px)`) уместны только для **изолированных** карточек с
собственным пространством вокруг (карточка склада `.warehouse-tile`, карточка
`.card`) — не для строк таблицы/списка.

Тактильный `:active` (нажатие) — да, везде, где уместен клик: лёгкое
`scale(0.96–0.97)` на кнопках и карточках, **не** на строках-таблицах
(там либо не делать, либо только явная смена фона на более тёмный акцент).

## Правило 3 — длительности и easing

| Что | Длительность | Easing |
|---|---|---|
| Смена фона (hover/active) | 120–180ms | `ease` |
| Появление/исчезновение (fade+small move) | 200–320ms | `cubic-bezier(0.22, 1, 0.36, 1)` |
| Пружинный «pop» (бейдж, FAB при появлении) | 200–250ms | `cubic-bezier(0.34, 1.56, 0.64, 1)` |

Не выходить за верхнюю границу 320ms для повторяющихся, часто вызываемых
действий (список продаж открывается десятки раз за смену) — иначе ощущается
как задержка/лаг, а не «живость».

## Правило 4 — списки появляются каскадом, но с потолком

Строки списка при первой отрисовке — лёгкое движение сверху (`translateY(-8px)
→ 0`) + fade, с задержкой `i * 25ms` на строку, **потолок 12 строк**
(`Math.min(i, 12) * 25ms`) — иначе длинный список из полусотни строк
«доигрывает» появление секундами, что раздражает при частом использовании.
Готовый паттерн — `.sale-history-row-in` в `index.css` (используется в
`SalePage.tsx` и `StockPage.tsx`), переиспользовать этот же класс/keyframe,
не плодить копии.

```css
.sale-history-row-in {
  animation: sale-history-row-in 0.32s cubic-bezier(0.22, 1, 0.36, 1) both;
  animation-delay: var(--row-delay, 0ms);
}
```

## Правило 5 — исчезновение перед размонтированием, не вместо него

Если элемент убирается условным рендером (`{condition && <X/>}`), React снимает
его с дерева мгновенно — анимации сыграть не успевают. Для элементов, которые
должны плавно исчезать (закрытие плавающей панели, очистка корзины и т.п.):
держать компонент смонтированным на время анимации через внутреннее состояние
(`closing`/`visible`) и `setTimeout`, соответствующий длительности анимации, и
только потом сообщать родителю, что можно убрать данные. Не размонтировать
раньше, чем доиграла анимация.

## Правило 6 — accessibility

Каждая анимация появления/движения оборачивается в
`@media (prefers-reduced-motion: reduce) { animation: none; }` — минимальная
цена, уважает системную настройку пользователя.

## Где уже применено (эталонные образцы для копирования паттерна)

- `.stock-row`, `.warehouse-tile`, `.product-tile`, `.warehouse-card` —
  hover/active по правилам 1–2.
- `.sale-history-row-in` — каскадное появление по правилу 4.
- `.restock-cart-trigger`/`.restock-cart-badge`/`.restock-cart-panel` —
  pop-анимация появления по правилу 3 (пружинный easing).
- `RestockCartMenu` (`WarehouseDetailPage.tsx`) — эталонная реализация
  правила 5. Паттерн: `hadItemsRef` хранит, был ли контент на предыдущем
  рендере; когда список пустеет, компонент не размонтируется сразу, а
  выставляет `leaving = true`, проигрывает `.restock-cart-trigger-out`
  (`index.css`, обратная анимация к `-in`, `0.2s ease`), и только через
  `setTimeout` чуть больше длительности CSS-анимации (220ms на 200ms анимации)
  реально скрывает себя (`if (items.length === 0 && !leaving) return null`).
  Копировать этот паттерн для любого другого «условно исчезающего» элемента
  (не плодить рефы/таймеры заново — выносить в общий хук, если появится
  третий случай).

## Голые `<table>` — полностью устранены (проход завершён)

По запросу пользователя все HTML-таблицы в проекте переведены на общий
div/grid-паттерн `.data-table`/`.data-table-head`/`.data-row`
(`index.css`, рядом с `.stock-row`, который стал основой этого паттерна).
Причина: `border-collapse` не даёт корректно анимировать/поднимать `<tr>`/`<td>`
(наткнулись на это при попытке сделать 3D-hover на таблице остатков), и вообще
голая таблица не может участвовать в едином визуальном языке карточек/плиток.

Паттерн:
- `.data-table` — внешняя рамка+радиус, аналог `.table-wrap`.
- `.data-table-head` — шапка колонок, `display: grid`, колонки через inline
  `style={{ gridTemplateColumns: '...' }}` (константа в начале файла страницы,
  например `EMPLOYEE_COLUMNS`), не через CSS-класс — потому что колонки у
  каждой таблицы разные, а сам паттерн общий.
- `.data-row` — строка, тот же `gridTemplateColumns`. Некликабельные строки —
  просто `.data-row` (Аудит, Аналитика, срочные долги). Кликабельные —
  `.data-row` + `.data-row-link` на `<button>`/`<Link>` (не на `<div>`!) —
  даёт hover (`accent-soft`), focus-visible, курсор.
- `.data-row-chevron` — опциональная стрелка справа для кликабельных строк
  (копирует `.warehouse-tile-chevron`: сдвигается и красится в акцент при
  hover родителя).
- Переменное число колонок (например, MovementForm показывает цену закупки
  только в режиме "Приёмка") — колонки вычисляются как обычная JS-переменная
  в теле компонента (`movementColumns = mode === 'receive' ? '...' : '...'`),
  **не** через IIFE в JSX — грязный код, испробовали и откатили.

Переведены: EmployeesPage, ClientsPage (клиенты+поставщики), DebtsPage
(срочные долги), AuditPage, AnalyticsPage (топ товаров, категории, мёртвый
остаток), SalePage (строки чека в деталях продажи), ProductDetailCard
(остатки по складам, варианты), ProductsPage (ошибки импорта),
MovementHistoryPage (строки документа). Отдельный более сложный кейс —
редактируемая корзина (`cart-table` с `<input>` полями кол-ва/цены,
степпером) в SalePage (чек) и `shared.tsx` (MovementForm, накладная
приёмки/списания/перемещения) — тоже переведена на div-grid, класс
`.cart-table-row`/`.cart-table-head` (не путать с общим `.data-row` — это
отдельный, более специфичный паттерн с полями ввода).

Также унифицированы карточки склада: `ProfilePage` (виджет "Ваши склады")
использовал устаревший `.warehouse-card`, теперь — тот же `.warehouse-tile`,
что и на `StockPage`. Старые классы `.warehouse-grid`/`.warehouse-card*`
удалены из CSS как полностью мёртвые.

`OrdersPage` таблиц не использует (карточки `.card.card-full`) — вне
области этого прохода.

## Каскадное появление — перенесено на все `.data-table`/списки (проход завершён)

Правило 4 (`.sale-history-row-in` + `--row-delay: Math.min(i, 12) * 25ms`)
применено ко всем спискам, которые его ещё не имели: `EmployeesPage`,
`ClientsPage` (клиенты и поставщики), `DebtsPage` (срочные долги),
`AuditPage`, `AnalyticsPage` (все три таблицы), `SalePage` (строки чека в
деталях продажи), `WarehouseDetailPage` (таблица остатков склада),
`ProductDetailCard` (остатки по складам, варианты), `ProductsPage` (сетка
товаров), `MovementHistoryPage` (карточки документов — не внутренняя
раскрывающаяся таблица строк документа, она разворачивается по клику, а не
при первой загрузке списка, каскад там не имеет смысла).

Не тронуто намеренно: таблица ошибок импорта в `ProductsPage` (одноразовый
результат внутри модалки после импорта — не список, который пользователь
видит регулярно, каскад — лишняя суета на редкое разовое действие).

Компонент рендерится и как `<div>`, и как `<button>` (кликабельные строки) —
класс общий, `transform`/`opacity` работают одинаково на обоих, разницы в
поведении нет.

## OrdersPage — переведён на `.data-table` (проход завершён)

Карточки заказов были на голом `.card.card-full.row.between` — та самая
«bootstrap»-рамка без hover/анимации, которую убирали везде остальном.
Заменено на `.data-table`/`.data-row` (`ORDER_COLUMNS = '2fr 1fr 1fr 1fr'`):
заказ+клиент+срок, сумма+доплата, статус-бейдж, кнопка перехода в
следующий статус. Строка — `<div>`, не `<button>` (внутри есть отдельно
кликабельная кнопка «→ Готов» и т.п., вложенные кнопки в `<button>`
недопустимы), поэтому своего hover на всю строку нет — только фон строки
как у остальных некликабельных `.data-row` (Аудит, срочные долги).
Каскадное появление (`sale-history-row-in`) добавлено сразу.

## Аудит модалок — все используют общий `Modal` (проверено)

Поиск по `.modal-overlay`/`role="dialog"`/`aria-modal` показал, что этот
разметочный паттерн существует только внутри самого `shared/ui/Modal.tsx` —
ни одна страница не реализует диалог вручную поверх голого JSX. Все 11
файлов, где есть модалки, используют компонент `<Modal>`, то есть уже
получают анимацию `modal-pop`/`modal-slide-up` бесплатно. Отдельных доработок
не требуется.
