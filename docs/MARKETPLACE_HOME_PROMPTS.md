# Главная страница маркетплейса «как на wikkeo»: промпты для ИИ-ассистента

> Перед началом — свериться с `docs/UX_SIMPLICITY_RULES.md`: тест на простоту и бюджет сложности экрана.

Страница: `/marketplace` (`frontend/src/pages/marketplace/MarketplacePage.tsx`).
Это публичная главная всего продукта (решение от 16.09, см.
`wikkeo_design_reference.md`). Там лента товаров сразу всех магазинов.

**Сейчас** на странице только поиск, фильтры и плоский список товаров.
Баннеров, категорий-плиток, ряда магазинов, подборок, скидок и нормальной
шапки нет. В ответе API нет `sold_count` и рейтинга (бэкенд их отдаёт,
а в типе фронта их нет), нет списка категорий и списка магазинов.

---

## Как пользоваться

Порядок работы:

1. `ILLUSTRATIONS_PROMPTS.md`, промпт **I1**: подготовить hero и
   onboarding, они нужны для баннеров.
2. **Бэкенд M-B1 → M-B3.**
3. **Фронтенд M-F0 → M-F6.**

Компонент `ProductCard` общий с карточкой товара (`PRODUCT_PAGE_PROMPTS.md`,
F8). Какая из серий пойдёт первой, та его и создаёт, вторая переиспользует.

## 1. Разбор скриншотов wikkeo и решения для ВайСклад

| Блок wikkeo | У нас | Почему так |
|---|---|---|
| Верхняя полоса: «Россия», «Управление магазином», «Новинки», «Для поставщиков», «Помощь», «Поддержка», переключатель темы | **Город** (Грозный, Урус-Мартан, Гудермес, Шали, Аргун, «Все города»), «Кабинет магазина», «Новинки», «Открыть магазин», «Помощь», «Поддержка» (Telegram), тема | Первый рынок — города Чечни, поэтому выбор города полезнее, чем «Россия» |
| Шапка: кнопка каталога, логотип, поиск «Везде ›», избранное, заказы, чат, корзина, аватар | То же. Поиск «Везде / в городе». Корзина **общая по всем магазинам**, сгруппированная по магазинам | Корзины у нас сейчас хранятся по магазинам (`loadCart(slug)`), нужна сводная |
| Чипы «Дропшиппинг», «Ликвидация» | Чипы-подборки: «Скидки», «Новинки», «Хиты продаж», «С высоким рейтингом», «Рядом со мной» (город) | Опт и дропшиппинг — не наша модель |
| Большая карусель баннеров со стрелками | Карусель баннеров из админки. Если баннеров нет, показываем слайд с нашим hero | Баннеры ведёт владелец платформы в `/admin` |
| 6 плиток категорий с фото | 6–8 плиток **платформенных категорий** с картинками | Категории у магазинов свои. Нужен общий справочник платформы и сопоставление с ним |
| Две промо-плитки: «Продавайте на Wikkeo, комиссия 0%», «Обзоры новых поставщиков» | «Откройте магазин бесплатно» (onboarding-иллюстрация) и «Отзывы реальных покупателей» (или второй баннер из админки) | Бесплатность — главное позиционирование ВайСклад |
| Ряд круглых логотипов магазинов | Так же: логотип, название, ★ рейтинг | Нужен список магазинов и логотипы (B2 из `PRODUCT_PAGE_PROMPTS.md`) |
| «Распродажа»: сетка по 5 | Секции «Скидки», «Хиты продаж», «Новинки», «С высоким рейтингом», «Магазины рядом» — каждая по 10 товаров и «Смотреть все ›» | |
| Карточка: фото 1:1, бейджи «-20% от 15К» и «Бесплатная доставка», название + ♡, цена + зачёркнутая, ★ 4.3, щит + магазин, «Продано: 57» | Фото 1:1, бейджи **«-20%»**, «Новинка», «Хит», «Нет в наличии»; название + ♡; цена + зачёркнутая старая; ★; значок проверенного магазина + имя магазина; «Продано: N» | «-20% от 15К» — оптовая скидка, её не делаем. Обычная скидка на товар — да, для этого нужно поле «старая цена». «Бесплатную доставку» не обещаем |
| Бесконечная лента | Внизу «Все товары» с фильтрами и «Показать ещё» (режим каталога) | Текущие фильтры не выбрасываем, а переносим в режим каталога |

**Режимы одной страницы:**

- **Витрина-главная** — без параметров поиска и фильтров.
- **Каталог** — есть `q`, `category`, фильтр или `section`. Это текущая
  страница, приведённая в порядок.

URL остаётся один (`/marketplace`), так ссылки из подборок работают сразу.

## Промпт M-B1 — справочник категорий платформы, город, проверенный магазин, старая цена

```text
Проект ВайСклад, бэкенд: FastAPI + SQLAlchemy 2 + Alembic + Postgres 16 +
Redis, чистая архитектура (domain / application / infrastructure /
presentation), multi-tenant. Изучи:
  app/presentation/marketplace/*, app/application/marketplace/*
  app/presentation/admin/router.py
  app/infrastructure/db/models/catalog.py, identity.py
  frontend/api_docs/marketplace.md, admin_status.md, README.md
Фронтенд не трогай. На всё — миграции Alembic, тесты pytest и записи
в frontend/api_docs (README.md + новый marketplace_home.md).

1. СПРАВОЧНИК КАТЕГОРИЙ ПЛАТФОРМЫ (глобальный, без tenant_id)
   Таблица platform_categories: id, name, slug (уникальный), image (путь),
   sort_order, is_active, parent_id (один уровень вложенности).
   Сид-миграция с базовым набором (slug латиницей): Электроника,
   Одежда, Обувь, Инструменты, Автотовары, Аксессуары, Продукты,
   Для дома, Красота, Детские товары, Строительство, Прочее.
   - Category (категория магазина) получает platform_category_id: int | null.
     Владелец выбирает его в своей категории: PUT категории принимает поле,
     GET отдаёт. Отдельный публичный GET /api/marketplace/categories
     владелец тоже использует для выпадающего списка.
   - Автосопоставление для существующих данных: одноразовый скрипт
     backend/scripts/map_platform_categories.py сопоставляет по
     нормализованному названию (lower, trim, ё→е) и словарю синонимов
     в domain (например «кроссовки», «туфли» → Обувь). Несопоставленные
     остаются null.
   - Админка (require admin, как у существующих /api/admin/*):
     GET/POST/PUT/DELETE /api/admin/platform-categories,
     POST /api/admin/platform-categories/{id}/image (multipart).
     DELETE — мягкое отключение (is_active=false), если есть привязки.
   - Публично: GET /api/marketplace/categories →
     [{ id, slug, name, image, parent_id, products_count }], только
     активные, products_count — видимые товары видимых магазинов
     (с учётом ?city=, см. п.2). Категории с 0 товаров не отдавать.
     Кэш 5 минут.
   - GET /api/marketplace/products: новый параметр
     platform_category=<slug> (включает дочерние категории). Старый
     category=<название> оставить для совместимости.

2. ГОРОД МАГАЗИНА
   Tenant.city: str | null. Справочник городов — константа в domain:
   Грозный, Урус-Мартан, Гудермес, Шали, Аргун, Курчалой,
   Ачхой-Мартан, Наурская, Другой (список легко расширить).
   - GET/PATCH /api/auth/shop принимают и отдают city (валидация по
     справочнику).
   - GET /api/marketplace/cities → [{ name, shops_count }] (только
     города, где есть магазины с включённой витриной).
   - GET /api/marketplace/products: параметр city.

3. ПРОВЕРЕННЫЙ МАГАЗИН
   Tenant.is_verified: bool (default false). Меняется только админом:
   POST /api/admin/tenants/{id}/verify и /unverify (по образцу
   suspend/unsuspend). В списке и деталке тенантов админки — поле
   is_verified.

4. СТАРАЯ ЦЕНА (обычная розничная скидка на товар, не оптовая)
   Product.compare_at_price: Decimal | null. В API товара владельца —
   чтение и запись. Валидация: null или строго больше retail_price
   (иначе 400 «Старая цена должна быть больше текущей»).
   Если позже retail_price поднимут выше старой цены — старую цену на
   витрине не отдавать (считать скидку отсутствующей), в БД не трогать.
   В ответах витрины и маркетплейса (список и карточка):
   old_price: string | null, discount_percent: int | null
   (округление вниз, показывать только при ≥ 3%).
   Фильтр with_discount=true в /api/marketplace/products и
   /api/storefront/{slug}.
   ВАЖНО: заявка с витрины по-прежнему считается по retail_price,
   compare_at_price на деньги не влияет.

5. ПОЛЯ КАРТОЧКИ МАРКЕТПЛЕЙСА
   В каждом товаре /api/marketplace/products добавить:
   shop_logo, shop_is_verified, shop_city, old_price, discount_percent,
   is_new (created_at за последние 14 дней), is_hit (входит в топ-10%
   по sold_count за 30 дней среди видимых товаров платформы, минимум
   5 продаж; считай пакетно, кэшируй на 10 минут).
   Логотип магазина — поле storefront_logo из B2 в
   PRODUCT_PAGE_PROMPTS.md. Если B2 ещё не сделан — сделай в этой
   задаче минимально: поле + загрузка через POST /api/auth/shop/logo.

6. НОВЫЕ СОРТИРОВКИ в /api/marketplace/products и /api/storefront/{slug}:
   popular (sold_count за 30 дней, по убыванию), rating (average_rating,
   затем reviews_count), discount (discount_percent по убыванию).
   Параметр min_rating уже есть.

7. ТЕСТЫ: сопоставление категорий по синонимам; фильтр по
   platform_category с дочерними; города и счётчики; verify только для
   админа; compare_at_price (валидация, скрытие при росте цены, на
   заявку не влияет); is_new и is_hit; новые сортировки; изоляция
   tenant и скрытые товары.

В конце: изменённые файлы, миграции, pytest.
```

## Промпт M-B2 — баннеры и данные главной одним запросом

```text
Проект ВайСклад, бэкенд (правила — как в M-B1). Фронтенд не трогай.

1. БАННЕРЫ ПЛАТФОРМЫ
   Таблица platform_banners: id, placement ('hero' | 'promo'), title,
   subtitle, button_text, link (внутренний путь /… или https://),
   image (путь), image_mobile (путь, необязательно),
   theme ('light' | 'accent' | 'dark' — фронт превращает это в цвета
   темы), sort_order, is_active, starts_at, ends_at (nullable),
   city (nullable — показывать только в этом городе).
   Админка: CRUD /api/admin/banners + загрузка двух картинок (multipart,
   тот же сервис хранения, что у фото товара, максимум 3 МБ).
   Валидация link: только относительный путь или https; javascript: и
   прочее — 400.

2. ГЛАВНАЯ ОДНИМ ЗАПРОСОМ
   GET /api/marketplace/home?city=<name>
   {
     banners: { hero: Banner[], promo: Banner[] },   // активные по датам и городу
     categories: PlatformCategory[],                  // первые 12 по sort_order с товарами
     shops: ShopChip[],                               // до 20
     sections: [
       { key: 'discount',  title: 'Скидки',               products: Product[] },
       { key: 'popular',   title: 'Хиты продаж',          products: Product[] },
       { key: 'new',       title: 'Новинки',              products: Product[] },
       { key: 'top_rated', title: 'С высоким рейтингом',  products: Product[] }
     ],
     stats: { shops_count, products_count, cities_count }
   }
   - ShopChip: { slug, name, logo, city, is_verified, average_rating,
     reviews_count, products_count }. Порядок: проверенные → с лого →
     по числу продаж за 30 дней. Магазины без товаров на витрине
     не показывать.
   - Product — тот же формат, что элемент /api/marketplace/products
     (со всеми полями из M-B1).
   - В каждой секции по 10 товаров, только в наличии. Секция, где меньше
     5 товаров, не отдаётся. top_rated: reviews_count ≥ 3 и рейтинг ≥ 4.5.
   - Разнообразие: не больше 3 товаров одного магазина в секции (жадный
     отбор по порядку сортировки).
   - Кэш 60 с на город, rate limit как у маркетплейса. Все агрегаты —
     пакетные запросы, без N+1. Добавь тест на число SQL-запросов
     (≤ 12), если в проекте есть такой приём. Если нет — логируй
     количество в тесте.

3. МАГАЗИНЫ
   GET /api/marketplace/shops?city=&query=&sort=popular|rating|new&limit=&offset=
   → { shops: ShopChip[], total }. Нужна для страницы «Все магазины».

4. ПОДСКАЗКИ ПОИСКА
   GET /api/marketplace/suggest?q=<от 2 символов>&city=
   → { products: [{ id, name, photo, price, shop_slug }] (до 5),
       shops: ShopChip[] (до 3),
       categories: [{ slug, name }] (до 3) }
   Поиск ILIKE по имени и артикулу, триграммы — если pg_trgm доступен.
   Кэш 30 с на запрос, rate limit 120/минуту.

5. Тесты: даты и город баннеров, валидация ссылок, правила секций
   (минимум 5, максимум 3 товара на магазин, только в наличии),
   порядок магазинов, suggest, скрытые и заблокированные магазины
   нигде не появляются.

6. Документация: marketplace_home.md с TS-типами всех ответов и разделом
   «Что сделать на фронте».
```

## Промпт M-B3 — общая корзина покупателя (необязательный, но желательный)

```text
Проект ВайСклад, бэкенд (правила — как в M-B1).

Сейчас корзина живёт только в localStorage и по магазинам отдельно.
На главной маркетплейса нужна одна иконка корзины с общим счётчиком,
а у авторизованного покупателя корзина должна переживать смену
устройства.

1. Таблица customer_cart_items (customer_id, tenant_id, product_id,
   variant_id nullable, quantity, updated_at), уникальна по
   (customer_id, product_id, variant_id).
2. GET /api/customer/cart → группы по магазинам:
   [{ shop_slug, shop_name, shop_logo, min_order_total,
      items: [{ product_id, variant_id, name, variant_label, photo,
                price, old_price, quantity, in_stock,
                min_order_qty, order_step_qty }],
      subtotal }]
   Цены и наличие — актуальные, из БД. Товары, ставшие невидимыми,
   приходят с in_stock=false и флагом unavailable=true.
3. PUT /api/customer/cart/items (upsert одной позиции, quantity=0 —
   удалить), POST /api/customer/cart/merge (фронт после входа отправляет
   локальные корзины, количества складываются с ограничением 9999),
   DELETE /api/customer/cart?shop_slug=… (после оформления заявки).
4. Все эндпоинты — только с customer JWT. Тесты, документация в
   customer_cart.md.
```

## Что сознательно не переносим

- **«-20% от 15К», «-3% от 9 шт», «Ликвидация», «Дропшиппинг».**
  Это оптовая модель. Обычная скидка на товар через старую цену — делаем.
- **«Бесплатная доставка», «Безопасная сделка», «Ваши деньги под
  защитой».** ВайСклад не принимает деньги и не доставляет товары.
  Такие обещания вводили бы покупателей в заблуждение.
- **Сине-жёлтый 3D-маскот и фирменные цвета wikkeo.** У нас свой
  плоский зелёный стиль. Новые картинки генерируйте по промпту I6 из
  `ILLUSTRATIONS_PROMPTS.md`.
- **Кросс-магазинная доставка и одна оплата за корзину из разных
  магазинов.** Заказ оформляется отдельно в каждом магазине.
