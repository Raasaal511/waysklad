# Довести публичные страницы до конца: витрина, карточка товара, маркетплейс

> Перед началом — свериться с `docs/UX_SIMPLICITY_RULES.md`: тест на простоту и бюджет сложности экрана.

Три страницы, которые видит покупатель:

1. `/marketplace` — общая витрина платформы
2. `/store/:slug` — каталог одного магазина
3. `/store/:slug/products/:id` — карточка товара

Сейчас они выглядят как три разных сайта: три разные шапки, разные отступы,
разные карточки товара, на маркетплейсе карточки вообще без стилей. Этот файл —
про то, чтобы сделать из них одну систему и довести до конца, без каши.

Порядок: **P0 → P7 по одному промпту**, каждый со своей проверкой.
Промпт «Д» (дизайн-система) — не задача, а справка: его текст вставляется
в начало каждого шага.

## 2. Промпт «Д» — дизайн-система публичных страниц

> Этот текст вставляйте **в начало каждого** промпта P0–P7. Он не меняется.
> Это единственный источник правды по размерам и цветам: если в шаге сказано
> иначе, прав этот блок.

```text
ДИЗАЙН-СИСТЕМА ПУБЛИЧНЫХ СТРАНИЦ ВАЙСКЛАД (обязательна к соблюдению)

0. Область. Публичные страницы: /marketplace, /store/:slug,
   /store/:slug/products/:id, /store/:slug/cart, /cart, /favorites,
   страницы ошибок. Кабинет владельца (внутренние экраны) не трогаем.

1. Цвета — ТОЛЬКО переменные из src/index.css:
   --bg, --bg-muted, --text, --text-muted, --border, --accent,
   --accent-hover, --accent-soft, --danger, --danger-bg, --warning,
   --warning-bg, --ink, --radius, --radius-sm.
   Хардкод цвета запрещён, кроме #fff внутри кнопки на --accent и
   градиента-оверлея поверх фото (rgba(0,0,0,…)).
   Фон страницы — var(--bg-muted). Контент — карточки var(--bg).
   Светлая тема: у карточек рамки НЕТ. Тёмная тема: рамка 1px var(--border).
   Обязательно работают: светлая и тёмная тема, все четыре data-accent.

2. Сетка и ширины:
   - контейнер 1280px, боковые поля: 24px (≥1024), 20px (768–1023), 16px (<768)
   - брейкпоинты: 1280, 1024, 768, 480
   - вертикальный ритм между крупными блоками: 48px (≥1024), 32px (<1024)
   - внутренний padding карточки: 24px (≥1024), 16px (<768)
   - шкала отступов: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64. Других нет.

3. Скругления: карточка и фото — 16px; вложенные элементы и кнопки — 12px;
   мелкое (миниатюра, бейдж) — 8px; чипы и круглые кнопки — 999px.

4. Типографика (размер/начертание/высота строки):
   - H1 страницы: 32/700/1.2 (24 на мобильном)
   - Заголовок секции: 24/700/1.25 (20 на мобильном)
   - Заголовок карточки-блока: 18/600/1.3
   - Цена крупная: 28/700; цена в карточке товара в сетке: 18/700
   - Основной текст: 16/400/1.5; вторичный: 14/400/1.45 var(--text-muted)
   - Подпись/бейдж: 12/600, uppercase только у бейджей
   Больше размеров не вводить. Переносы: заголовки — не более 2 строк
   (line-clamp), длинные слова — overflow-wrap: anywhere.

5. Кнопки:
   - основная: высота 48 (44 на мобильном), radius 12, фон var(--accent),
     текст #fff, hover var(--accent-hover), active scale .99
   - вторичная: тот же размер, фон var(--accent-soft), текст var(--accent)
   - тихая (ghost): прозрачная, текст var(--text-muted), hover фон var(--bg-muted)
   - иконочная: 44×44 (40 на мобильном), radius 12
   - круглая «+»: 32×32, фон var(--accent), иконка #fff 18px, stroke 2
   - отключённая: opacity .5, cursor not-allowed, без hover-эффектов
   - у КАЖДОЙ кнопки есть :focus-visible — outline 2px var(--accent),
     offset 2px. Убирать outline запрещено.

6. Бейджи (на фото товара, снизу слева, колонкой, gap 4):
   скидка — var(--danger) на var(--danger-bg);
   «Новинка» — var(--accent) на var(--accent-soft);
   «Хит» — var(--warning) на var(--warning-bg);
   «Нет в наличии» — var(--text-muted) на var(--bg-muted), фото opacity .6.
   Одновременно не больше двух, приоритет: нет в наличии → скидка → хит → новинка.

7. Фото:
   - в карточке товара в сетке: aspect-ratio 1/1, object-fit cover
   - главное фото на странице товара: aspect-ratio 4/5, object-fit contain,
     фон var(--bg-muted)
   - миниатюра варианта: 48×48, radius 8
   - у всех <img> заданы width/height или aspect-ratio (нулевой CLS),
     loading="lazy" кроме первого экрана, alt = название товара
   - нет фото → ProductPhoto-плейсхолдер, никогда не «битая картинка»

8. Состояния — есть у каждого блока, который грузит данные:
   загрузка (skeleton той же геометрии, shimmer выключается при
   prefers-reduced-motion), пусто, ошибка, успех. Пустое состояние и ошибка —
   через shared/ui/EmptyState и shared/ui/ErrorState с иллюстрациями из
   public/illustrations (см. docs/ILLUSTRATIONS_PROMPTS.md):
   пустой каталог — empty-shelf; ничего не найдено по фильтрам — без
   картинки, текст + «Сбросить фильтры»; пустая корзина — empty-cart;
   нет отзывов — empty-box; товар/витрина не найдены — error-404-not-found;
   магазин заблокирован — error-403-blocked; ожидание Telegram —
   state-telegram-confirm.

9. Анимации: 150ms для hover, 250ms для появления, 300–450ms для каруселей,
   кривая ease-out. Любая анимация выключается при prefers-reduced-motion.
   Никаких прыгающих макетов: skeleton занимает столько же места, сколько
   контент.

10. Числа, деньги, склонения (частый источник мусора на экране):
    - деньги: formatMoney + « ₽» через неразрывный пробел
    - количества: formatQuantity — «5», а не «5.000»; бэкенд отдаёт Decimal
      строкой, печатать её напрямую запрещено
    - единицы: product.unit_label («шт», «кг»), не хардкод «шт»
    - склонения: единая функция plural(n, ['товар','товара','товаров']);
      «1 товаров» — дефект
    - рейтинг: одна цифра после точки, «5.0»
    - даты: относительные до 30 дней («вчера», «3 дня назад»), дальше —
      «16 сентября 2026»; месяц в родительном падеже
    - пустые значения не печатаем: нет отзывов — не «0 отзывов», а «Нет
      отзывов»; sold_count 0 — бейджа нет

11. Доступность: у иконочных кнопок aria-label; у изображений alt;
    порядок табуляции естественный; модалки и лайтбокс — фокус-ловушка,
    Esc, возврат фокуса; контраст текста ≥ 4.5:1 в обеих темах;
    вложенных <a> внутри <a> нет (ссылка на всю карточку — через ::after).

12. Запреты:
    - новые npm-зависимости
    - inline-стили, кроме CSS-переменных (например style={{'--delay':…}})
    - :global, !important, хардкод px там, где есть переменная
    - второй компонент того же назначения (вторая карточка товара, вторая
      шапка, второй степпер) — вместо этого дорабатывается существующий
    - «пока оставлю старое рядом» — заменённый код удаляется в том же шаге
```

## 5. Правила против каши (действуют на всех шагах)

1. **Один шаг — один коммит.** Сообщение в стиле проекта: `frontend: …`.
   Не смешивать рефакторинг и новую функциональность в одном коммите.
2. **Сначала удалить, потом добавить.** Если новый компонент заменяет
   старый, старый удаляется в том же шаге. «Временно оставлю» запрещено.
3. **Не изобретать четвёртое.** Прежде чем создать компонент, поискать
   существующий: `grep -r "название" src`. Если похожий есть — дорабатывать его.
4. **Не трогать бэкенд и кабинет владельца.** Если для красивого экрана не
   хватает поля — не выдумывать, а написать в отчёте.
5. **Каждый шаг заканчивается скриншотами**, и ассистент сам на них
   смотрит, а не пишет «должно выглядеть хорошо».
6. **Отчёт по каждому шагу в одном формате:** что сделано, что не сделано
   и почему, какие файлы добавлены/удалены, какие вопросы остались.
7. **Не больше трёх кругов правок на шаг.** Если после третьего круга
   что-то не сходится — остановиться и спросить.
