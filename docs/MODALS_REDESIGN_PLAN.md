# План: редизайн модалок — компактность и удобство работы

Запрошено пользователем: существующие модалки "неприятны и сложно в них работать".
Разбор на примере `ProductForm` (создание/редактирование товара) выявил конкретные
проблемы, актуальные для всех длинных форм в проекте (Заказ, Задача, Склад, Продажа).

## Проблемы, найденные на скриншотах (до)

1. Плоская одноколоночная форма без визуальной иерархии — «Название» (главное поле)
   выглядело так же, как «Штрихкод» (второстепенное).
2. Кнопка сохранения не закреплена — нужно было скроллить всю форму до конца, чтобы
   её найти, хотя `Modal.tsx` уже поддерживал sticky `footer`, просто не все формы
   его использовали.
3. Вложенные модалки: «+ Категория» / «+ Единица измерения» внутри формы товара,
   «+ Клиент» внутри формы продажи — открывали `Modal` поверх `Modal`, с двойным
   затемнением фона. Пользователь отдельно попросил это убрать: "надо сделать
   инпуты для обновления или дропдаун чтобы не было вложенных модалок".
4. Баг: тултип "Закрыть" на крестике модалки перекрывал сам крестик на мобильном.
5. Артикул товара предзаполнялся случайным числом сразу при открытии формы —
   отвлекает внимание от первого поля, которое должен заполнить пользователь.

## Статус: частично реализовано

Реализовано (эта сессия):
- `shared/ui/InlinePopover.tsx` (новый) — компактная поповер-панель у
  кнопки-триггера вместо модалки поверх модалки. Позиционирование от
  `getBoundingClientRect`, закрытие по клику вне/Escape — тот же паттерн,
  что уже был в `Select`/`InfoHint`.
- Устранена вложенность модалок в 3 местах: `QuickNewCategoryForm`,
  `QuickNewUnitForm` (`ProductsPage.tsx`), `QuickNewClientForm` (`SalePage.tsx`) —
  переведены с `<Modal>` на `<InlinePopover>`.
- `.form-section-title` (CSS) — лёгкий заголовок-разделитель секции внутри формы
  (граница сверху + подпись caps), без рамки-коробки как у `.field-group`.
- `ProductForm` переструктурирована в секции: Название/Цены/Категория →
  «Учёт и остаток» (единица, начальный остаток, мин. остаток) → «Идентификация»
  (артикул, штрихкод) → «Дополнительно» (фото, варианты).
- Кнопка сохранения вынесена в `footer` модалки через HTML `form`-атрибут
  (`<Button type="submit" form={PRODUCT_FORM_ID}>` снаружи, `<form id={PRODUCT_FORM_ID}>`
  внутри) — видна сразу без скролла, паттерн уже использовался в `NewSaleForm`.
- `.form-fieldset` — блокирует и притемняет все поля формы во время сохранения
  (`disabled={saving}`), убирает возможность повторного сабмита.
- Убран тултип с кнопки закрытия модалки (`Modal.tsx`) — иконка "X"
  самообъясняющая, тултип на мобильном перекрывал сам крестик.

Не реализовано (следующие шаги, см. ниже) — тот же паттерн предстоит применить к:
- `NewOrderForm` / `OrderDetail` (`OrdersPage.tsx`, самая длинная форма в проекте —
  клиент, склад, источник, срок, позиции, предоплата).
- `NewTaskForm` (`TasksPage.tsx`) — короче, но выигрывает от группировки
  общая/дозаказ-специфичные поля уже частично разделены визуально, стоит добавить
  `.form-section-title`.
- `WarehouseEditForm`, `MovementForm` (`stock/shared.tsx`, `WarehouseDetailPage.tsx`).
- `NewSaleForm` — уже использует `footer`, но сама форма (поиск товара, корзина,
  оплата) не разбита на `.form-section-title`, стоит проверить нужно ли.

## Идеи из референса (yclients.com, раздел Склад)

Из документации/обзоров вытащены конкретные UX-решения, которые применимы к
нашему стеку без архитектурных изменений:

1. **Инвентаризация — автосохранение без кнопки "Сохранить".** В yclients любое
   изменение строки при инвентаризации сохраняется автоматически. У нас
   `MovementForm`/`WarehouseEditForm` требуют явный сабмит — это нормально для
   разовых операций (приёмка, списание — нужен явный момент "подтверждаю"), но
   стоит взять на вооружение для **инвентаризации**, если/когда будет
   реализована как отдельный длинный процесс сверки остатков: каждое введённое
   фактическое количество сохраняется сразу, без риска потерять час работы из-за
   случайного закрытия вкладки.
2. **Цветовая индикация изменённых строк.** В таблице инвентаризации
   белый = без изменений, синий = отредактировано вручную. Применимо к нашему
   `MovementForm` (список строк приёмки/списания/перемещения) — сейчас все строки
   выглядят одинаково, независимо от того, тронул их пользователь или это
   дефолтное значение. Небольшая точечная правка: подсветка `background`/`border`
   у строки, где `quantity` отличается от изначального.
3. **Поиск товара с быстрым действием по Enter.** В инвентаризации yclients:
   нашёл товар в поиске → Enter → остаток сразу +1, без отдельного клика "добавить".
   У нас в `MovementForm`/`NewSaleForm` добавление товара уже по клику на тайл —
   стоит проверить, работает ли Enter на выделенном результате поиска
   (клавиатурный флоу для частого сценария "сканирую/ищу пачку позиций подряд").
4. **Длинные многошаговые процессы — не модалка, а отдельная страница/панель.**
   yclients выносит инвентаризацию в собственный полноэкранный раздел, а не в
   модальное окно. У нас `NewOrderForm`/`NewSaleForm` уже открываются как
   `size="full"` модалка, что близко к этому паттерну — но стоит помнить это
   правило при добавлении новых длинных процессов: если процесс кандидат на
   "сессию работы" дольше пары минут (инвентаризация, массовая приёмка) — лучше
   отдельная страница с постоянным URL, чем `size="full"` модалка, которую легко
   случайно закрыть кликом по фону/Escape.
5. **Дата и время подставляются автоматически, но остаются редактируемыми.**
   В форме создания инвентаризации дата/время предзаполнены текущим моментом.
   У нас это уже частично так (`due_date` в заказах, `DateInput`) — держать как
   принцип по умолчанию для новых форм с датой.

- [YCLIENTS — Управление складами](https://support.yclients.com/5-11-315--upravlenie-skladami/)
- [YCLIENTS — Создание и настройка нового склада](https://support.yclients.com/5-11-313--sozdanie-i-nastrojka-novogo-sklada/)
- [YCLIENTS — Склад (раздел)](https://support.yclients.com/5-11--sklad/)

Примечание: справочные страницы yclients рендерятся через JS и не отдают полный
текст статичным `fetch`, поэтому детали визуального оформления (макет полей,
расположение кнопок) взяты из фрагментов, попавших в поисковую выдачу и кеш —
это текстовое описание поведения, не скриншоты. Если нужна точная визуальная
сверка макета, стоит открыть демо-аккаунт yclients напрямую.

## Дальнейшие шаги (порядок по приоритету)

1. `NewOrderForm` (`OrdersPage.tsx`) — самая длинная и жалуемая форма, применить
   `.form-section-title` (Клиент/контакты → Позиции → Срок/предоплата) +
   проверить, есть ли там вложенные модалки для клиента (аналогично `SalePage`).
2. `MovementForm` (`stock/shared.tsx`) — добавить цветовую подсветку
   изменённых строк (идея #2 из yclients) для приёмки/списания/перемещения.
3. `NewTaskForm` — добавить `.form-section-title` между общими полями и
   дозаказ-специфичными (уже частично разделены логикой, не визуально).
4. Пройтись по оставшимся модалкам (`WarehouseEditForm`, `SaleReturn`,
   `EmployeeForm`) на предмет: (a) длинных плоских форм без секций,
   (b) незакреплённой кнопки сохранения, (c) вложенных модалок.
