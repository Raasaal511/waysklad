# Задача: личный кабинет покупателя + подтверждение телефона кодом

**Статус:** к реализации
**Дата постановки:** 2026-09-21
**Объём:** бэкенд ~1 день, фронтенд ~1–1.5 дня
**Что уже есть:** регистрация и вход покупателя по логину и паролю,
вход по ссылке в Telegram, `GET/PUT /api/auth/customer/me`,
`GET /api/storefront/requests/my`, чат по заявке, избранное в localStorage

---

## Зачем

Сейчас покупатель после входа не имеет своего места в системе: заявки
видны только по ссылке, имя и телефон нигде не показываются, статус
заявки приходится спрашивать в чате. Нужен один экран, куда покупатель
заходит и видит: кто он, подтверждён ли телефон, что он заказывал и на
какой стадии заказ.

Подтверждение телефона нужно магазину: по этому номеру продавец
перезванивает и по нему же отличает реальную заявку от мусорной.

---

## Важное решение перед стартом: чем слать код

SMS требует платного провайдера (SMS.ru, SMSC и подобные): договор,
деньги за каждое сообщение, модерация подписи отправителя. Для пилота это
лишние расходы и время.

Поэтому: **код отправляем в Telegram-бот**, который уже работает. Отправка
кода прячется за интерфейсом, чтобы SMS можно было подключить позже, не
переписывая логику:

```
IVerificationCodeSender
  ├── TelegramCodeSender  — сейчас, бесплатно, бот уже есть
  ├── ConsoleCodeSender   — для dev и тестов (код в лог)
  └── SmsCodeSender       — позже, когда появится провайдер
```

Выбор реализации — из настроек (`VERIFICATION_SENDER=telegram|console`).
Если у покупателя нет `telegram_chat_id`, показываем ссылку на бота:
«Откройте бота и нажмите Старт, мы пришлём код».

---

## Как работать (протокол)

1. Сначала план в чат: какие файлы тронешь, что в каждом, какие места
   нашёл неочевидными, вопросы. Код не трогай до моего «ок».
2. После «ок» — по пунктам сверху вниз, один пункт = один коммит.
3. После каждого пункта отчёт не длиннее 10 строк: файлы, суть, чем
   проверено.
4. Правила экономии контекста из `CLAUDE.md` действуют.
5. Нашёл что-то за рамками списка — в отчёт, не в код.

## Часть A — бэкенд

- [ ] **A1. Модель.** `Customer.phone_verified: bool = False` и
  `phone_verified_at: datetime | None`. Таблица `customer_phone_codes`:
  `customer_id`, `phone`, `code_hash`, `attempts`, `expires_at`,
  `created_at`, `sent_via`. Миграция. Код в открытом виде не хранить.

- [ ] **A2. Отправка кода.** `POST /api/auth/customer/phone/request-code`
  (JWT покупателя), тело пустое — телефон берём из аккаунта.
  Правила: код 6 цифр, живёт 5 минут; повторная отправка не чаще раза в
  60 секунд (в ответе `retry_after`); не больше 5 запросов в час на
  аккаунт; старые неиспользованные коды гасятся. Ответ:
  `{ sent_via, retry_after, telegram_deep_link }` — ссылка заполнена,
  когда у покупателя нет `telegram_chat_id`.

- [ ] **A3. Проверка кода.** `POST /api/auth/customer/phone/verify`
  `{ code }`. Успех — `phone_verified=true`, `phone_verified_at=now`,
  код гасится. Ошибки: `400` неверный код (с остатком попыток),
  `400` просрочен, `429` попытки кончились (не больше 5 на код).
  Тексты `detail` — готовые для показа пользователю.

- [ ] **A4. Профиль.** `GET /api/auth/customer/me` дополнить:
  `phone_verified`, `phone_verified_at`, `created_at`, `requests_total`,
  `requests_active`, `shops_count` (в скольких магазинах заказывал).
  `PUT` — если меняется телефон, `phone_verified` сбрасывается в `false`.

- [ ] **A5. Список заказов.** `GET /api/storefront/requests/my` дополнить
  тем, чего не хватает карточке заказа: `created_at`, `shop_slug`,
  `shop_name`, `shop_logo`, состав с названием, фото, количеством и
  ценой позиции, сумма заявки, а для принятых — `due_date`, `total`,
  `prepayment`, `to_pay`, статус заказа. Пагинация `limit`/`offset`
  (по умолчанию 20) и фильтр `status`.
  Проверь, что отдаётся одним запросом без N+1.

- [ ] **A6. Смена пароля покупателя.**
  `PATCH /api/auth/customer/me/password` `{ current_password, new_password }`
  и `POST /api/auth/customer/me/logout-all` — по образцу тех же
  эндпоинтов владельца (`token_version` у `Customer` уже есть).
  Если аккаунт заведён без пароля (вход только через Telegram) — вместо
  смены пароля разрешить его установку без текущего.

- [ ] **A7. Тесты** на всё выше: срок жизни кода, лимит попыток,
  повторная отправка раньше минуты, смена телефона сбрасывает
  подтверждение, чужой заказ не виден, пагинация. Плюс запись в
  `frontend/api_docs/README.md` и новый файл
  `frontend/api_docs/customer_profile.md` с TS-типами.

Заявки покупателям **не блокируем** по неподтверждённому телефону —
это отдельное решение, не в этой задаче.

## Часть B — фронтенд

Маршрут `/account` (в кабинете владельца `/profile` уже занят). Общая
публичная шапка и подвал, дизайн-правила — блок «Д» из
`docs/PUBLIC_PAGES_FINISH_PROMPTS.md`. Mobile-first.

- [ ] **B1. Каркас.** Не авторизован → экран входа (существующая форма),
  после входа возврат на `/account`. Авторизован → страница профиля.
  На десктопе две колонки: слева навигация по разделам, справа контент.
  На мобильном — вертикальный список разделов, каждый открывается как
  отдельный экран, сверху кнопка «Назад».

- [ ] **B2. Карточка профиля.** Аватар-кружок с первой буквой, имя,
  логин, телефон. Под телефоном — статус: «Телефон подтверждён» (галочка,
  `--accent`) или «Телефон не подтверждён» (`--warning`) и кнопка
  «Подтвердить». Кнопка «Изменить» открывает форму имени и телефона;
  при смене телефона предупреждаем, что подтверждение слетит.
  Ниже мелко: «С нами с сентября 2026», «Заказов: 7, активных: 1».

- [ ] **B3. Подтверждение кодом (модалка).**
  Шаг 1 — «Отправим код в Telegram» и кнопка «Отправить код». Если в
  ответе есть `telegram_deep_link` — сначала экран «Откройте бота и
  нажмите Старт», с кнопкой-ссылкой и иллюстрацией
  `state-telegram-confirm`.
  Шаг 2 — ввод кода: шесть отдельных клеток, автофокус, переход между
  ними по вводу и Backspace, вставка кода из буфера целиком, только
  цифры, на мобильном цифровая клавиатура (`inputMode="numeric"`,
  `autocomplete="one-time-code"`). Под полем таймер «Отправить повторно
  через 0:47», после нуля — активная ссылка. Ошибки из `detail` под
  полем, клетки подсвечиваются `--danger`, поле не очищается полностью.
  Успех — модалка закрывается, статус обновляется, тост «Телефон
  подтверждён».

- [ ] **B4. Мои заказы.** Список заявок, новые сверху, бесконечная
  подгрузка по 20. Фильтр-чипы: «Все», «Новые», «Приняты», «Отклонены».
  Карточка заказа: логотип и название магазина (ссылка на витрину),
  дата, статус-бейдж (новая — `--board-new`, принята — `--accent`,
  отклонена — `--text-muted`), до трёх миниатюр товаров и «ещё N»,
  сумма. Для принятой — строка «Готово к <дата> · к оплате <сумма>».
  Кнопки: «Чат с магазином» (существующий чат по заявке) и «Повторить
  заказ» (кладёт те же товары в корзину этого магазина, недоступные
  пропускает и сообщает об этом).
  Тап по карточке раскрывает полный состав.
  Пусто → `EmptyState` с иллюстрацией `empty-archive`, текст «Здесь
  появятся ваши заказы» и кнопка «Перейти к покупкам».

- [ ] **B5. Избранное.** Раздел со списком избранных товаров (данные из
  localStorage по ключам магазинов, карточки — общий `ProductCard`).
  Пусто → `empty-box`, кнопка «В каталог».

- [ ] **B6. Безопасность и выход.** Раздел «Настройки»: смена пароля
  (или установка, если пароля нет), «Выйти», «Выйти на всех
  устройствах». Подтверждение перед выходом со всех устройств.

- [ ] **B7. Вход в профиль из интерфейса.** В публичной шапке аватар
  покупателя ведёт в `/account`; в меню аватара — «Мои заказы»,
  «Избранное», «Выйти». На мобильном — пункт «Профиль» в нижней панели.

- [ ] **B8. Состояния и проверка.** Скелетоны на загрузке, ошибка сети с
  кнопкой «Повторить», 401 → экран входа без падения страницы.
  Скриншоты 375 и 1440, светлая и тёмная тема: профиль с подтверждённым
  и неподтверждённым телефоном, модалка кода (пустая, с ошибкой, с
  таймером), список заказов (пустой, с тремя заказами разных статусов).
  `npm run build` и `npm run lint` чистые.

## Что НЕ входит

- SMS-провайдер и оплата рассылок — только интерфейс под него.
- Блокировка заявок для неподтверждённых покупателей.
- Адреса доставки, привязка карт, уведомления — у нас нет ни доставки,
  ни оплаты.
- Перенос избранного и корзины на сервер — отдельная задача.

---

## Приёмка

Покупатель заходит на `/account`, видит своё имя и телефон, за две
минуты подтверждает телефон кодом из Telegram, видит список своих
заказов со статусами, открывает чат по заказу и может повторить заказ.
Всё это работает на телефоне одной рукой.
