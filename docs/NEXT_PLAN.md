## Приоритет 1 — реально блокирует обещание продукта

1. ⬜ **Бэкап на внешнее хранилище** (`deploy/backup.sh:19`, открытый TODO).
   Сейчас бэкап пишется только на тот же хост, что и БД — при потере
   диска/сервера обещание README §6.5 («ежедневные бэкапы + недельная копия
   на отдельное хранилище») не выполняется. П.13 плана прямо называет потерю
   данных потерей доверия навсегда. Сделать: rclone (или scp) на внешнее
   хранилище (S3-совместимое/другой VPS), недельная ротация отдельно от
   ежедневной локальной. Небольшая, но критичная задача — можно закрыть за
   одну короткую сессию.

2. ⬜ **Health-check backend в `docker-compose.prod.yml`.** Сейчас
   healthcheck настроен только для `db`/`redis`, у `backend` — нет. Плюс сам
   `GET /api/health` тривиален (`{"status":"ok"}`, без проверки БД/Redis) —
   контейнер может быть "up", но не обслуживать реальные запросы (например,
   БД отвалилась), и никто не узнает, кроме зависшего пользователя. Сделать:
   расширить health-check реальной проверкой соединения с БД (и Redis в
   проде), завести `healthcheck:` для сервиса `backend` в compose.

## Приоритет 2 — реальный сценарий пилота, но не блокирует старт

3. ⬜ **Офлайн-очередь продаж в долг на фронте** (TECH_DEBT №6, вторая
   половина). Backend готов (`OfflineSaleRequest.debt_due_date`), но
   frontend-очередь (IndexedDB) ещё не кладёт такие продажи в офлайн-пачку.
   Оплата в долг без интернета — по README один из самых частых сценариев в
   регионе. **Это фронтенд-задача** (моя scope — backend-only), но стоит
   держать в поле зрения и, возможно, обсудить с фронтенд-разработчиком
   отдельно — не моя задача чинить, но не должно потеряться.

4. ⬜ **`warehouse_id` на Order/Debt/Client/Supplier** (TECH_DEBT №5).
   Актуально только при 2+ складах у одного tenant — для типичного пилотного
   магазина (1 склад = 1 точка) не критично. Стоит поднять в приоритете
   только когда появится первый пилот с реально несколькими точками.

5. ⬜ **`GET /api/inventory/documents/{id}`** (TECH_DEBT №9). Точечный
   запрос вместо полного списка документов на фронте — не создаёт проблем
   при объёме пилота (5-20 магазинов), но дешёвая и понятная задача, если
   будет свободная сессия.
