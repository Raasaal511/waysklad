# Задача: спрятать витрину в кабинете владельца за флаг

**Статус:** к реализации
**Дата постановки:** 2026-09-21
**Объём:** фронтенд, примерно полдня
**Бэкенд:** НЕ ТРОГАТЬ — ни схемы, ни эндпоинты, ни миграции, ни тесты бэка

---

## Зачем

Для пилотных магазинов витрина сейчас не нужна: владелец заводит остатки,
пробивает продажи и ведёт долги. Витринные поля на форме товара
(«Показывать на витрине», «Фото для витрины», «Описание», «Мин. количество
для заказа», «Шаг заказа») добавляют пять понятий, которые придётся
объяснять на каждом внедрении, и удлиняют форму там, где владелец заводит
сотни позиций.

Решение: витрина остаётся в коде и на бэкенде целиком, но в кабинете
показывается только тем магазинам, у которых она включена.

**Флаг уже существует:** `Tenant.storefront_enabled`, по умолчанию `false`,
приходит в `GET /api/auth/shop`, меняется через `PATCH /api/auth/shop`.
Новых флагов, переменных окружения и настроек заводить не нужно.

**Вкладку «в разработке» не делаем.** Раздел, помеченный «скоро», — это
обещание, которое придётся объяснять владельцу на каждом внедрении.
Выключено — значит не видно вовсе.

---

## Как работать (протокол)

1. **Сначала план, потом код.** Прочитай задачу, найди все места в коде и
   напиши в чат: какие файлы будешь менять, что именно в каждом, чего
   трогать не будешь, какие нашёл неочевидные места, какие есть вопросы.
   Ничего не меняй до моего «ок».
2. После «ок» — по пунктам списка ниже, сверху вниз. После каждого пункта
   короткий отчёт: файлы, суть правки, чем проверено.
3. Один пункт — один коммит, сообщение в стиле проекта (`frontend: …`).
4. Если по ходу находишь ещё одно место, где вылезает витрина, — не
   додумывай: добавь его в отчёт и спроси.
5. Ничего не удаляй: только скрывать. Значения полей в базе и в запросах
   не меняются.

## Список к реализации

- [x] **1. Один источник флага.** `GET /api/auth/shop` уже отдаёт
  `storefront_enabled` (подтверждено — читается из `ShopContext`, который
  и так грузит весь `Tenant` при старте). Хук `useFeature('storefront')`
  в `src/shared/lib/useFeature.ts` (не `useStorefrontEnabled()` — назван
  общее, на случай будущих флагов, семантика та же). Коммит `022adff`.

- [x] **2. Навигация.** `RequireFeature` (`src/app/RequireFeature.tsx`)
  оборачивает маршруты `/storefront` и `/orders/storefront-requests` в
  `App.tsx` — редирект на `/` через `Navigate replace`, без страницы
  ошибки. Пункт меню «Витрина» фильтруется в `AppLayout.tsx` тем же
  хуком. Коммит `f3d0014`.

- [x] **3. Форма товара.** Секция «Витрина» в `ProductForm.tsx` (чекбокс,
  фото, описание, гарантия, мин. количество, шаг заказа — это одна
  JSX-секция в коде, не отдельные поля) обёрнута в
  `{storefrontEnabled && (...)}`. State не тронут — значения уходят в
  PUT такими же, как были. Подтверждено вручную (см. «Проверка» ниже):
  PUT-ответ при выключенном флаге содержит прежний `description`,
  `show_on_storefront: true`, `storefront_min_qty`. Коммит `bf156fd`.

- [x] **4. Карточка товара.** Секция «Витрина» и секция отзывов в
  `ProductDetailPage.tsx` скрыты тем же хуком; бейдж «На витрине» в
  шапке карточки — тоже (не в исходном списке буквально, но то же поле,
  бессмысленно показывать при выключенном флаге). Коммит `a90b498`.

- [x] **5. Настройки склада.** Чекбокс «Показывать на витрине» в
  `WarehouseDetailPage.tsx` скрыт. Заодно скрыты бейдж «На витрине» и
  кнопка «Поделиться витриной склада» в шапке страницы склада — увидел
  по ходу (п.4 протокола: не додумывать, писать в отчёт) и решил, что
  это те же данные без дополнительного значения при выключенном флаге,
  раз чекбокс, который их производит, недоступен. Коммит `9bd2fad`.

- [x] **6. Переключатель в профиле.** `StorefrontSettings` в
  `ProfilePage.tsx` (вкладка «Персонализация») теперь содержит
  переключатель «Онлайн-витрина» с подписью «Бета: каталог магазина по
  публичной ссылке», вызывает существующий `updateShop({ storefront_enabled })`
  → `PATCH /api/auth/shop`, обновляет `ShopContext` через `setShop` —
  все скрытые в 2-5 блоки появляются сразу, без reload (подтверждено).
  Коммит `e42c49e`.

- [x] **7. Проверка и скриншоты.** Выполнено вручную в браузере (dev-аккаунт
  +79280000001, tenant «WaySklad»), не только статическим анализом кода:

  - форма товара короче при выключенном флаге, блок «Витрина» отсутствует

  - пункт «Витрина» пропадает из меню (sidebar и mobile bottom-nav)

  - прямой заход на `/storefront` при выключенном флаге → редирект на

  - сохранение товара с выключенным флагом не теряет витринные поля —
    подтверждено PUT-ответом API (`description`, `show_on_storefront`,

## Что НЕ входит в задачу

- Публичные страницы `/store/:slug`, `/store/:slug/products/:id`,
  `/marketplace` и всё под ними — остаются как есть. При выключенной
  витрине бэкенд и так отдаёт 404, отдельная заглушка не нужна.
- Любые правки бэкенда, включая «заодно переименовать» и «заодно добавить
  поле».
- Удаление витринного кода, компонентов и стилей.
- Доработка самой витрины (шаги P0–P7 из `PUBLIC_PAGES_FINISH_PROMPTS.md`) —
  отдельная задача, после пилота.

---

## Приёмка

Задача считается закрытой, когда у магазина с `storefront_enabled: false`
владелец не видит ни одного упоминания витрины, а после включения флага
вся функциональность возвращается в прежнем виде, без потери данных.
