# Что брать в работу и в каком порядке

Короткий путеводитель по всем отчётам в этой папке — чтобы не читать всё
подряд. Один файл = одна тема, здесь только порядок и статус. Если что-то
не попало в этот список — можно пока не трогать, это либо справочный
материал, либо уже сделано.

---

## 🔴 Срочно — делает сломанным то, что уже работает

### 1. Авторизация покупателей (`customer_auth.md`)
Сейчас `StorefrontCartPage.tsx` шлёт заявку анонимно (`customer_phone` в
теле запроса). После обновления бэкенда это перестанет работать:
`POST /storefront/{slug}/requests` требует `Authorization: Bearer`, поле
`customer_phone` из тела убрано вообще. **Без правки фронта оформление
заказа с витрины сломается полностью** (401 на каждую попытку).

Что делать: добавить экран входа (телефон → ссылка на Telegram-бота →
поллинг статуса → сохранить токен), убрать поле телефона из формы заказа,
подставлять `Authorization` в запрос создания заявки. Всё расписано пошагово
в файле, включая рекомендованную частоту поллинга.

**Это не горит сегодня** (бэкенд ещё не на проде), но должно закрываться
первым — самое большое по объёму и самое рискованное, если отложить.

## 🟡 Дёшево и полезно — маленькие правки, час-два работы каждая

Можно делать в любом порядке, не блокируют друг друга.

### 2. Генератор штрихкода (`product_barcode_generate.md`)
Одна кнопка на форме товара + один запрос без параметров
(`POST /products/barcode/generate`). Результат просто вписывается в
существующее поле штрихкода на форме.

### 3. Невзятая сдача (`sale_change_kept.md`)
Новое поле `change_kept` в форме продажи/выдачи заказа с оплатой наличными.
**Важно:** поле `change` в ответе теперь означает сдачу, реально выданную на
руки — если где-то в UI уже показывается `change`, стоит свериться с новым
смыслом при апдейте.

### 4. Бейдж «Продано: N» на витрине (`storefront_sold_count.md`)
Новое поле `sold_count` в ответах каталога/карточки товара витрины — просто
вывести значение, если не 0. Backend уже всё считает.

### 4b. Тот же бейдж + рейтинг в маркетплейсе (`marketplace.md`)
`GET /api/marketplace/products` теперь тоже отдаёт `sold_count`/
`average_rating`/`reviews_count` на каждой карточке — то же самое, что в
пункте 4, просто в общей ленте маркетплейса.

## 🟢 Можно взять как отдельную фичу, когда будет время

### 5. Приватная admin-панель (`admin_status.md`)
Отдельный раздел, не для покупателей/владельцев магазинов — статус сервера,
список магазинов платформы, блокировка магазина. Средний объём (свой логин
через `POST /api/admin/login`, несколько списков/карточек). Не блокирует
ничего в основном продукте — можно брать отдельной задачей в любой момент.

### 6. Описание товара + AI-генерация + галерея фото (`product_description.md`)
Три связанных поля на карточке товара: `description` (текст), кнопка
«Сгенерировать через ИИ», и `storefront_photos` (отдельная от складского
фото галерея для витрины — загрузка/переупорядочивание/удаление). Средний
объём — новый блок на форме товара + карточка на витрине.

### 7. Аналитика «Упущенные продажи» (см. запись в `README.md` за 2026-09-14)
Новый эндпоинт `GET /api/analytics/missed-sales` — таблица рядом с
существующими «Топ товаров»/«Неликвиды» на странице аналитики. Не срочно,
чисто дополнительный отчёт для владельца.

### 7b. Личный профиль покупателя (новый раздел в `customer_auth.md`)
`GET/PUT /api/auth/customer/me` — имя покупателя + сводная статистика заявок.
Небольшой объём: экран профиля + автоподстановка имени в форму заказа.

### 8. Отзывы и рейтинг (`reviews.md`)
Новый домен: покупатель с принятой заявкой оставляет отзыв (1-5 звёзд, текст,
фото) на товар; владелец модерирует (скрыть/вернуть) в своей панели. Каталог
и карточка товара на витрине получили `average_rating`/`reviews_count`.
Средний-крупный объём: форма отзыва на карточке товара, звёзды в каталоге,
вкладка модерации в панели владельца. Backend полностью готов, включая
контракт и тесты.
