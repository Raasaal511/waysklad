# Бейдж «Продано: N» на витрине

Новое поле `sold_count` в ответах публичной витрины — сколько единиц товара
продано за всё время (обычные офлайн-продажи и продажи через витрину вместе,
не разделяются). Не поле товара (в `GET /api/products/{id}` для владельца его
нет) — это витринный агрегат, посчитанный на лету, того же рода, что уже
существующий `in_stock`.

---

## Где приходит

- `GET /api/storefront/{slug}/products` (список каталога) — у каждого товара
  есть `sold_count: string` (десятичная строка, как остальные количества/суммы
  в API — `Decimal` на бэке).
- `GET /api/storefront/{slug}/products/{id}` (карточка одного товара) — тоже
  есть `sold_count: string`.

Товар без единой продажи — `sold_count: "0"`, не отсутствие поля.

## Точность

Считается по `SaleLine.quantity` всех непустых (не удалённых полностью)
продаж товара за всё время — без ограничения по периоду. Частичные возвраты
(`SaleReturn`) число не уменьшают — тот же принцип приближения, что уже
используется в существующей аналитике («Топ товаров» и т.п.), не новая
неточность.

## Что нужно сделать на фронте

1. В списке каталога витрины — небольшая плашка/бейдж «Продано: N» на карточке
   товара (рядом с ценой или поверх фото — см. `wikkeo_design_reference.md`,
   идея оттуда, но оформить в цветах ВайСклада, не копировать их стиль).
   Если `sold_count` равен `0` — по аналогии с общим подходом «не показываем
   пустые/незначимые бейджи», разумно скрыть плашку вовсе, а не показывать
   «Продано: 0» (решать на фронте).
2. На детальной карточке товара — то же значение можно показать рядом с
   рейтингом/остальными метриками, когда появятся отзывы (см. отдельную
   будущую фичу — гистограмма рейтинга).
