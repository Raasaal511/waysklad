# Невзятая сдача (округление в пользу магазина)

Новое поле `change_kept` — для случая «клиент заплатил больше и не взял
сдачу» (например, цена 5890₽, клиент отдал 5900₽ и не забрал 10₽). Раньше
такой сценарий никак не фиксировался: `cash_received` без явного «не забрал»
приводило к тому, что сдача просто не показывалась/не считалась, а сама
переплата нигде не учитывалась.

---

## Как это устроено

`change_kept` — сумма из сдачи, которую клиент добровольно не забрал.
Хранится отдельно от `discount` и от цены товара — это **не скидка** и не
меняет `Sale.total` (цену чека). Деньги реально остаются в кассе сверх
стоимости товара, поэтому учитываются отдельной метрикой в аналитике, не
смешиваясь с выручкой по товарам.

## Что меняется в запросах

**`POST /api/sales`** (обычная продажа) и **`POST /api/orders/{id}/issue`**
(выдача заказа) — оба теперь принимают необязательное поле:
```json
{ "cash_received": "5900", "change_kept": "10", ... }
```
- `change_kept` имеет смысл **только вместе с `cash_received`** (нельзя
  «не взять сдачу» без указания, сколько денег внесли наличными) — иначе
  `400`.
- `change_kept` не может быть больше фактической сдачи
  (`cash_received - total`) — иначе `400`.
- Если `change_kept` не передан — по умолчанию `0`, поведение как раньше,
  ничего не сломано.

## Что меняется в ответе

`SaleResponse` (оба эндпоинта возвращают его в конечном итоге):
```ts
{
  ...
  cash_received: string | null,  // как и раньше — сколько внесено
  change: string | null,         // ИЗМЕНИЛОСЬ: теперь это сдача, реально
                                  // выданная на руки — за вычетом change_kept.
                                  // В примере выше change = "0.00", не "10.00"
  change_kept: string,           // НОВОЕ — сколько из сдачи клиент не забрал
}
```

## Аналитика

**`GET /api/analytics/totals`** (и дашборд, который его использует) — новое
поле `change_kept: string` в ответе, рядом с `revenue`/`profit`. Это сумма
невзятой сдачи за период — **не входит** в `revenue`/`profit`, отдельная
цифра (по замыслу — накопленная переплата, а не выручка по товарам).

## Что нужно сделать на фронте

1. На экране продажи/выдачи заказа с оплатой наличными — после ввода
   `cash_received`, если получившаяся сдача не равна 0, показать кнопку/чекбокс
   «Клиент не взял сдачу» рядом с суммой сдачи к выдаче.
2. Если отмечено — можно позволить указать частичную сумму (клиент забрал
   часть мелочи, часть оставил) или по умолчанию вся сдача = `change_kept`
   (сдача к выдаче становится 0). На усмотрение UX, бэк поддерживает любую
   сумму `change_kept` до фактической сдачи включительно.
3. Отправлять `change_kept` вместе с `cash_received` в теле запроса создания
   продажи/выдачи заказа.
4. На экране «Аналитика» (там же, где `revenue`/`profit` за период) — можно
   добавить отдельную строку/плашку «Невзятая сдача: N ₽» из нового поля
   `change_kept` в ответе `GET /api/analytics/totals`.
