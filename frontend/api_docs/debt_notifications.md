# Долги: мгновенные уведомления, анти-спам low-stock, сообщение клиенту

Три доработки поверх уже описанного в `README.md` (долги, in-app/Telegram
уведомления, low-stock). Ничего не ломает существующие контракты — только
новый эндпоинт и новый вид уведомления в уже существующем канале.

---

## 1. Мгновенное уведомление при выдаче долга

Раньше долг попадал в уведомления только через ежедневный cron
(`notify_due_debts` — просроченные/скоро истекающие). Теперь **в момент
выдачи** долга (клиенту, поставщику, или продажа в кредит) owner и manager
магазина получают уведомление сразу — тем же каналом, что и остальные
(`GET /notifications`, WebSocket `/notifications/ws`, Telegram — только
владельцу).

Новый `kind` в уже существующей модели `Notification`:

```
"debt_issued"
```

Текст вида `Новый долг клиенту «Ибрагим» на 1500 ₽`, `link` ведёт на
`/debts?highlight={debt_id}` — как и у остальных видов долговых уведомлений,
ничего нового на фронте подключать не нужно (существующий `NotificationBell`
уже это отрендерит).

---

## 2. Low-stock больше не спамит каждый день

Раньше уведомление «заканчивается товар» повторялось каждый день, пока
остаток был ниже порога — даже если магазин ничего не мог сделать (товар
не подвезли). Теперь одно уведомление на «эпизод»: следующее придёт только
если остаток **вырос** с прошлого уведомления (была попытка пополнить, но
всё ещё мало) — если ничего не изменилось, тишина. Чисто backend-логика,
на фронте менять нечего.

---

## 3. WhatsApp-сообщение клиенту при выдаче долга/рассрочки

**`GET /api/debts/{debt_id}/receipt`** → `200`, `DebtReceiptResponse`
(только для долга клиента — у долга поставщику вернёт `400`).

```ts
{
  text: string,           // готовый текст сообщения
  whatsapp_link: string | null,  // wa.me-ссылка с текстом; null — у клиента нет телефона/WhatsApp
}
```

Тот же паттерн, что уже используется у чека продажи
(`GET /api/sales/{id}/receipt`) — открываете `whatsapp_link` в новой вкладке/
кнопкой «Отправить в WhatsApp», ничего не отправляется автоматически с
backend.

Пример текста (при оформленной рассрочке):

```
ВайСклад — Магазин
Оформлен долг №42
Клиент: Юсупов Расул Магомедович
Товар: 17 AIR 256, Б/У, 3 ЦИКЛА
Сумма: 84700 ₽
Ежемесячный платёж: 11200 ₽
Дата платежа: 10-е число каждого месяца
Остаток: 84700 ₽
```

- «Товар» — берётся из `note`, указанного при выдаче долга/оформлении
  рассрочки (свободный текст, не отдельная сущность «состав долга»).
- «Ежемесячный платёж»/«Дата платежа» показываются только если у долга есть
  график рассрочки (`POST /debts/{id}/installments`) — берётся первый ещё не
  оплаченный платёж графика. Если рассрочки нет, но есть `due_date`
  («обещал вернуть до») — вместо этого одна строка «Срок: ДД.ММ.ГГГГ».
- Рассрочка в проекте беспроцентная (сумма графика всегда равна остатку
  долга) — наценки/процента в сообщении нет и не предполагается сейчас.

**На фронте:** кнопка «Отправить клиенту в WhatsApp» на экране долга —
рядом с местом, где выдаётся долг или создаётся график рассрочки; дёргает
этот эндпоинт и открывает `whatsapp_link`, как уже сделано для чека продажи.
